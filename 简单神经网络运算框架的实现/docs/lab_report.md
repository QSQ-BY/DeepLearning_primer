# 简单神经网络运算框架实验报告

## 1. 项目概况

这是我目前写过的最长、规模也最大的一个项目。它只依赖 Python、NumPy 和标准库，实现了一个很小的神经网络运算框架。框架里有线性层、ReLU、二维卷积、Flatten、BatchNorm、Softmax 交叉熵、SGD 和顺序模型，也能读取 IDX 格式的 Fashion-MNIST 数据，完成前向传播、反向传播、参数更新和模型评估。

它离成熟框架还很远。项目没有池化层、自动求导、GPU、模型保存，也没有对卷积做向量化。不过，这次实验的目的本来就不是重新做一个 PyTorch，而是把平时写在纸上的公式拆开，确认每个中间量怎样落到 NumPy 数组上，梯度又怎样沿着网络一层层传回来。

## 3. 框架怎样工作

框架没有自动求导。每个网络层都显式实现四个接口：

```python
forward(x) -> output
backward(grad_output) -> grad_input
parameters() -> list[np.ndarray]
gradients() -> list[np.ndarray]
```

一次训练的数据流是：

```text
IDX 文件
→ load_idx_images / load_idx_labels
→ 打乱并生成小批量
→ Sequential.forward
→ SoftmaxCrossEntropyLoss.forward
→ SoftmaxCrossEntropyLoss.backward
→ Sequential.backward
→ SGD.step
```

`Sequential.forward()` 按保存顺序调用每一层，`backward()` 则倒序调用。无参数层返回空的参数列表，所以优化器只会收到真正需要更新的权重、偏置、`gamma` 和 `beta`。这套接口很简单，但它让全连接层、卷积层、激活函数和 BatchNorm 能用同一种方式组合。

实际的反向遍历只有几行，节选自 [`mininn/model.py`](../mininn/model.py)：

```python
for layer_index in range(len(self.layers)-1,-1,-1):
    layer = self.layers[layer_index]
    gradient = layer.backward(gradient)
```

本项目的设计亮点，是让所有层遵守同一套接口，再用单层测试和训练案例分别检查它们能否独立工作、能否接到一起。

### 3.1 基础层与损失函数

线性层计算

\[
Y=XW+b
\]

反向传播中，输入、权重和偏置的梯度分别为

\[
\frac{\partial L}{\partial X}=\frac{\partial L}{\partial Y}W^T,
\qquad
\frac{\partial L}{\partial W}=X^T\frac{\partial L}{\partial Y},
\qquad
\frac{\partial L}{\partial b}=\sum_n\frac{\partial L}{\partial Y_n}.
\]

ReLU 前向把非正数变为 0，反向只保留前向输入大于 0 的位置。Softmax 交叉熵先让 logits 减去每行最大值，再计算指数和对数，避免大数指数溢出。SGD 最后按照

\[
\theta \leftarrow \theta-\eta\nabla_\theta L
\]

原地更新参数。

### 3.2 卷积、展平与批量归一化

图像统一采用 NCHW 排列。二维卷积的输出高度为

\[
H_{out}=\left\lfloor\frac{H+2P-K}{S}\right\rfloor+1,
\]

宽度同理。当前实现使用多重循环遍历样本、输出通道和空间位置，在每个位置提取窗口，与卷积核对应相乘后求和。`Flatten` 保留批次维，把 `(N,C,H,W)` 变为 `(N,C\times H\times W)`，反向传播时再恢复原形。

BatchNorm 同时支持二维和四维输入。训练时使用当前批次的均值与方差，并更新运行统计量；推理时只使用运行统计量。二维输入按批次轴统计，NCHW 输入则跨 `N、H、W` 对每个通道分别统计。这个模式切换后来也进入了 Fashion-MNIST 的训练和评估循环。

统计轴和参数广播形状在 [`mininn/layers.py`](../mininn/layers.py) 中由输入维数决定：

```python
if x.ndim == 2:
    axes = 0
    broadcast_shape = (1,self.num_features)
elif x.ndim == 4:
    axes = (0,2,3)
    broadcast_shape = (1,self.num_features,1,1)
```

### 3.3 数据读取

Fashion-MNIST 使用 IDX 文件。读取图像时，程序先用 `struct.unpack(">4I", ...)` 解析魔数、样本数、高度和宽度，再用 `np.frombuffer` 把剩余字节解释成 `uint8` 像素。读取器按照文件头记录的高度和宽度把图像恢复为 `(N,1,H,W)`；对 Fashion-MNIST 来说就是 `(N,1,28,28)`。随后，数组被转换成 `float64` 并除以 `255.0`。标签文件的流程相似，但头部只有魔数与标签数量。

这一部分让我接触到的已经不只是神经网络。我还练习了 gzip 文件读取、二进制头解析、字节缓冲区转换、命令行参数和不同数据类型之间的转换。

## 4. 真正困难的是把公式写成代码

如果只看最后的公式和作用，很多层似乎并不复杂。真正开始写以后，我才发现“看懂公式”和“能写成可靠的 NumPy 代码”完全不是一回事。公式可以省略很多默认关系，代码却必须明确每个轴、每次广播、每个缓存和每一个需要累加的位置。

卷积反向传播是整个项目里最难的一段。前向传播中的一个输入位置可能被多个滑动窗口覆盖，同一个卷积核也会用于所有样本和空间位置。因此，输入梯度和权重梯度不能简单赋值，而要把每一次贡献累加起来：

```python
gradient = grad_output[
    batch_index,
    output_channel,
    output_row,
    output_column,
]
self.grad_weight[output_channel] += input_window * gradient
grad_padded_input[
    batch_index,
    :,
    row_start:row_end,
    column_start:column_end,
] += self.weight[output_channel] * gradient
```

这里最重要的是两个 `+=`。纸面上写一句“根据链式法则求和”很快，代码却必须找到正确的窗口，把不同输出位置的梯度放回同一片输入区域。再加上批次、输入通道、输出通道、步幅和填充，四维数组很容易在脑中混在一起。

BatchNorm 又是一个很大的难点。它的公式更集中，这里我偷了一点小懒，直接找的现成的公式，并没有像线性层和卷积层那样去想它具体的复杂推导，但后续的实现还是很不容易，训练和推理走的是两套统计量，二维输入与四维输入的归约轴也不同。我必须同时处理广播形状、运行均值、运行方差和反向传播缓存。以前看到“按通道归一化”时觉得意思很清楚，实际写代码才知道这句话至少还缺少统计轴、参数形状和模式状态。

我处理这两个难点的方法也不同。卷积层先把输出位置映射回输入窗口，再对重复覆盖的位置累加梯度；BatchNorm 则先确定二维和四维输入各自的统计轴及广播形状，训练时更新运行统计量，评估时切换为使用运行统计量。这样拆开后，我能逐项检查哪里算错，而不用同时盯着整段公式。

这次实验最直接地改变了我对“理解”的判断。现在如果我只会复述公式，却说不清数组是什么形状、梯度要沿哪些轴求和，我不会再觉得自己已经真正掌握了这一层。

## 5. 测试也是实现过程的一部分

这个项目的开发过程大体按 TDD 的思路推进：先确定一个很小的行为，写出测试并看到它失败，再补上能让它通过的实现，最后运行完整回归。

我以前更容易把测试理解成代码写完后的检查。这次测试直接参与了实现。比如卷积层不是一次写完，而是先检查类和参数形状，再处理单通道前向、多通道、stride、padding，最后拆开检查偏置、权重和输入梯度。面对一个很长的反向传播函数时，这种顺序让我至少知道当前只需要想清楚哪一件事。

测试还逼着我处理正常例子之外的情况：没有调用 `forward()` 就执行 `backward()`、上游梯度形状错误、IDX 魔数不正确、文件数据被截断、图片和标签数量对不上等等。

测试花了我不少时间。按当前 Python 文件的物理行数统计，`tests/` 有 2,536 行，`mininn/` 和 `examples/` 合计 1,208 行。读者不需要逐行看测试，但写用例时，我得先弄清楚一层网络怎样使用、必须满足哪些输入条件、错误输入该怎样报错。这个过程既练了代码，也是在重新想一遍框架的行为。

我还在测试里接触了 `unittest.TestCase`、`with self.subTest(...)`、用 `with tempfile.TemporaryDirectory()` 管理临时文件，以及用 `try/except/else` 检查异常。它们不是额外凑出来的代码：例如检查错误梯度形状时，我需要确认抛出的是 `ValueError`，提示中也说清了预期形状。

## 6. 这不是我独立从零写出的项目

说实话，这个项目不能算是我一个人从空白独立写出来的。整个过程都是跟着 Codex 老师一步步推进的：先解释公式和形状，再把任务拆小，给出代码骨架，我继续填写、运行并修改。项目中相当一部分代码是我跟着示例“抄”下来的，真正完全由我自己设计并写出的部分很少。

这一点需要写清楚。我可以说自己把这些代码敲进了项目，也跟着测试走完了实现过程，但还不能说离开提示以后，我已经能完整重写所有层的反向传播。尤其是 Conv2D 和 BatchNorm，很多细节仍然需要回头看公式与现有实现。

不过，亲手把代码输入、运行、看见错误，再沿着错误查回去，和只看一份现成代码并复制粘贴还是有区别。至少我现在知道困难具体在哪里，而不是仅仅让流程在自己的脑子里简单过一遍。

## 8. Fashion-MNIST 实验

### 8.1 网络结构

实际模型为：

```text
输入 (N, 1, 28, 28)
→ Conv2D(1, 4, kernel_size=3, stride=2, padding=1)
→ BatchNorm(4)
→ ReLU
→ Conv2D(4, 8, kernel_size=3, stride=2, padding=1)
→ BatchNorm(8)
→ ReLU
→ Flatten
→ Linear(392, 20)
→ BatchNorm(20)
→ ReLU
→ Linear(20, 10)
```

模型共有 8,470 个可训练参数。两次步长为 2 的卷积把空间尺寸从 `28×28` 依次缩小为 `14×14` 和 `7×7`，最后输出十个类别的 logits。

### 8.2 实验配置

| 项目 | 配置 |
| --- | --- |
| Python | 3.14.5 |
| NumPy | 2.5.0 |
| 训练样本 | 2,000 |
| 测试样本 | 1,000 |
| batch size | 32 |
| learning rate | 0.05 |
| epoch | 10 |
| 随机种子 | 42 |

从项目目录运行：

```powershell
python -m examples.train_fashion_mnist `
  "..\.build\fashion-mnist\train-images-idx3-ubyte.gz" `
  "..\.build\fashion-mnist\train-labels-idx1-ubyte.gz" `
  "..\.build\fashion-mnist\t10k-images-idx3-ubyte.gz" `
  "..\.build\fashion-mnist\t10k-labels-idx1-ubyte.gz"
```

### 8.3 实验结果

| Epoch | 训练损失 | 训练准确率 | 测试损失 | 测试准确率 | 耗时 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 1.477389 | 55.40% | 1.053819 | 67.50% | 14.91s |
| 2 | 0.941395 | 71.40% | 0.831459 | 73.20% | 15.51s |
| 3 | 0.752122 | 75.50% | 0.714793 | 74.80% | 15.54s |
| 4 | 0.651080 | 78.15% | 0.641378 | 77.90% | 14.41s |
| 5 | 0.584342 | 81.00% | 0.615385 | 79.60% | 14.40s |
| 6 | 0.511460 | 82.75% | 0.568525 | 80.30% | 15.56s |
| 7 | 0.495844 | 83.50% | 0.584394 | 80.30% | 15.36s |
| 8 | 0.439967 | 85.65% | 0.534490 | 81.70% | 14.74s |
| 9 | 0.402919 | 86.95% | 0.540428 | 82.10% | 16.25s |
| 10 | 0.372161 | 86.45% | 0.540318 | 81.20% | 14.79s |

训练损失从 `1.477389` 降到 `0.372161`，最终测试准确率为 `81.20%`，最高测试准确率出现在第 9 轮，为 `82.10%`。十轮总耗时约 `151.47s`，平均每轮约 `15.15s`。

表中的训练损失和训练准确率是在每个小批次更新参数时累计得到的加权平均值，并不是 epoch 结束后用最终参数重新计算的结果；测试指标则在该轮训练结束后统一评估。

后几轮训练损失仍在下降，但测试损失已经停在约 `0.53～0.58`，测试准确率也在 `80%～82%` 之间波动。以这个小模型和 2,000 个训练样本来看，它已经足够有效，但继续增加 epoch 未必会带来同样明显的泛化提升。

## 9. 目前的不足

最明显的问题是速度。卷积前向和反向都使用 Python 多重循环，计算量大致随 `N×C_out×H_out×W_out×C_in×K²` 增长。当前 2,000 个训练样本每轮训练与测试评估合计约 15 秒。改用 `im2col`、NumPy 向量化或编译扩展，是后续可以尝试的优化方向。

框架本身也只覆盖了最基础的一组功能，甚至没有池化，更别说其他的非顺序模型以及SGD以外的优化器了。Fashion-MNIST 实验只用了完整数据集的一小部分，结果不能与成熟框架的标准训练结果直接比较，但也算是非常扎实的一次深度学习入门项目。

完成这个项目以后，我最确定的一件事是：把神经网络写出来，比把公式抄在笔记上难得多。至于这些实现有多少已经真正成为我自己的能力，现在还不能只凭一次训练成功下结论。至少下一次再遇到四维张量、广播和梯度累加时，我知道应该从形状、缓存和最小测试开始，而不是只盯着最后一条公式。
