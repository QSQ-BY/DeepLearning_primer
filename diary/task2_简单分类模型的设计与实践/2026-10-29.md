## 先把文本变成编号

数据处理的第一步是统一分词规则。目前采用转小写后提取连续英文字母和数字的方式，标点会被忽略。例如 `Apple news!` 会得到 `['apple', 'news']`。这个规则比较简单，像缩写和带连字符的词会被拆开，后面可以再根据实验效果考虑是否调整。

接着统计训练文本的词频，建立“词 → 编号”的词表。`Counter.update()` 会累加每个词的出现次数，同一个词在一句话里出现两次，也会计数两次。普通词先按频率从高到低排列，同频时按字母顺序排列，让编号规则固定下来。当前配置只保留至少出现两次的词，词表上限为 50000，其中包含 `<PAD>` 和 `<UNK>`。

我现在把这几步分开理解：分词得到 token，词表给 token 分配编号，Embedding 再根据编号查出可训练的词向量。编号只是索引，编号相邻的词没有因此获得相近的语义。

下面是 [data.py](../../task2_简单分类模型设计与实现/news_classifier/data.py) 中的文本编码函数：

```python
def encode(text: str, vocab: dict[str, int], max_length: int) -> list[int]:
    #将整个文本转换为词编号
    if(max_length < 1):
        raise ValueError("max_length 必须大于等于 1")
    tokens = tokenize(text)
    tokens = tokens[:max_length]

    unk_id = vocab["<UNK>"]
    input_ids = [vocab.get(token,unk_id) for token in tokens]

    if(not input_ids):
        input_ids = [unk_id]
    return input_ids
```

这里先截断 token 列表，再按原文顺序逐个查表。找不到的词使用 `<UNK>` 的编号 1，空文本或者只有标点的文本也会得到 `[1]`，让后续至少有一个位置可以处理。`max_length=256` 限制的是 token 数量。

词表只从划分后的训练部分构建。验证集和测试集都复用这张词表，保证同一个词始终对应同一个编号，也避免提前利用验证和测试文本的信息。

## DataLoader 每次提供一个批次

`prepare_data()` 负责把读取、划分、建词表和编码串起来。我从官方训练集中按类别划出 10% 作为验证集，官方测试集保持独立。这里需要看清两个 `test`：`split['test']` 是从官方训练集中划出来的验证部分，`dataset['test']` 才是官方测试集。

编码后的单条样本是 `(词编号列表, 类别)`。DataLoader 取出一批这样的样本，再交给 `collate_batch()` 右侧补零，返回三个张量：

| 张量 | 内容 | 形状 |
|---|---|---|
| `input_ids` | 填充后的词编号 | `[B, L]` |
| `lengths` | 填充前的有效长度 | `[B]` |
| `labels` | 每条新闻的正确类别 | `[B]` |

填充长度取本批最长序列的长度，同时至少达到最大卷积核宽度 5。这样短句能通过卷积层，较短的批次也不必全部补到 256。

我还专门确认了 `batch_size` 的含义。设置为 64，表示每个批次最多处理 64 条新闻；默认情况下，最后一个不足 64 条的批次也会保留。`len(loader.dataset)` 是样本数，`len(loader)` 是批次数。一个 epoch 遍历一次训练集，每个批次通常更新一次参数。例如 1000 条样本、批量大小 64，会分成 16 个批次，最后一批有 40 条。

## TextCNN 的维度怎样连接

模型先把 `[B,L]` 的编号矩阵转换成 `[B,L,D]` 的词向量。`Conv1d` 要求输入按照“批次、通道、序列长度”排列，因此需要用 `x.transpose(1, 2)` 把它换成 `[B,D,L]`。这里词向量的维度就是卷积的输入通道，卷积核沿着 token 序列滑动。

当前初始配置如下，这些数值还没有经过正式实验比较：

| 配置项 | 当前设置 |
|---|---|
| 词向量维度 | 128 |
| 卷积核宽度 | 3、4、5 |
| 每个分支的输出通道数 | 128 |
| Dropout 概率 | 0.5 |
| 分类输出维度 | 4 |
| 批量大小 | 64 |
| 配置中的训练轮数 | 10 |
| 配置中的初始学习率 | 0.001 |

三个卷积分支接收同一份词向量，分别提取连续 3、4、5 个 token 的局部特征。输入通道数和输出通道数目前都是 128，但它们含义不同：前者由词向量维度决定，后者表示这个分支学习多少种卷积特征。

每个分支沿序列方向做最大池化后，留下 `[B,128]` 的结果。三个分支拼接成 `[B,384]`，经过 Dropout 和 `Linear(384,4)`，得到四个类别的原始分数。池化保留每个通道最强的响应，也会丢掉这个最大值在句子中出现的具体位置。

## 补零以后，还要限制池化范围

我看到初始化函数里没有单独定义池化层时，又确认了一次池化放在哪里。当前实现是在 `forward()` 中直接调用 `max()`，池化本身没有需要训练的参数，可以用张量操作完成。

不过，变长句子补齐以后，卷积会计算填充区域的响应。即使 PAD 对应的词向量为零，卷积偏置和包含部分真实 token 的窗口仍然可能产生数值。因此，池化前要根据真实长度排除无效窗口。

下面摘自 [model.py](../../task2_简单分类模型设计与实现/news_classifier/model.py) 的单个卷积分支，仅省略空行：

```python
valid_counts = (lengths - kernel_size + 1).clamp(min=1)
positions = torch.arange(
    features.size(2),
    device=features.device,
).unsqueeze(0)
valid_mask = positions < valid_counts.unsqueeze(1)
# 无效窗口不参与最大值竞争。
features = features.masked_fill(
    ~valid_mask.unsqueeze(1),
    float("-inf"),
)
# 沿序列方向池化：[B, F, L-k+1] → [B, F]
pooled = features.max(dim=2).values
pooled_features.append(pooled)
```

真实长度为 4、卷积核宽度为 3 时，完全位于文本内的窗口有 `4-3+1=2` 个。位置编号与这个数量比较后，得到每句话的有效窗口掩码。掩码增加一个通道维，就能限制这句话的全部输出通道。无效位置填成负无穷，再沿序列方向取最大值。

`clamp(min=1)` 还约定了短句的处理方式：句子短于卷积核时，保留左侧第一个含右侧补零的窗口，避免所有窗口都被屏蔽。这时保留的窗口包含 PAD，和正常句子的完整文本窗口需要区分。

当前前向传播处理的数据形状可以连起来看：`[B,L] → [B,L,128] → [B,128,L]`，接着分别卷积、池化，再拼成 `[B,384]`，最后输出 `[B,4]`。

## Dropout 和训练模式

Dropout 放在拼接后的新闻特征与分类层之间。训练时，每个特征值有 0.5 的概率被置零，保留下来的值乘以 `1/(1-p)`，保持输出的期望不变。每次前向传播都会重新随机选择，模型因此需要利用不同的特征组合进行分类。

它作用的是中间特征值，张量仍然是 `[B,384]`。参数仍保留在模型中，后续训练会继续使用。

验证时调用 `model.eval()`，Dropout 停止随机丢弃；`torch.no_grad()` 则关闭梯度记录。两者分别控制层的运行行为和自动求导，所以验证函数同时使用了它们。

## 单轮训练和验证

训练函数现在会遍历 DataLoader，将当前批次放到指定设备，计算预测和损失，再更新参数。下面是 [engine.py](../../task2_简单分类模型设计与实现/news_classifier/engine.py) 中的更新步骤：

```python
optimizer.zero_grad(set_to_none = True)

#进行前向传播，计算预测分数和损失
logits = model.forward(input_ids,lengths)
loss = criterion(logits,labels)

loss.backward()
optimizer.step()
```

`zero_grad()` 清除旧梯度，`backward()` 根据损失计算当前梯度，`step()` 再由优化器更新参数。分类层输出的 logits 直接交给交叉熵，训练前不额外做 Softmax。

统计整轮损失时，还要照顾最后一个不足批次的情况。默认交叉熵返回当前批次的平均损失，所以先乘以本批样本数累计，最后除以总样本数。准确率同样是总正确数除以总样本数。验证函数复用这个统计方式，但只进行前向计算，不更新参数也不进行反向传播。
