# Word2Vec：用中心词预测上下文

> 日期：2026 年 10 月 8 日
> 代码：[word2Vec.py](../../source/4.自然语言处理/1.Word2Vec/word2Vec.py)
> 这篇记录依据当前代码和本次实际运行结果整理。

这次我用 PyTorch 写了一个小型 Word2Vec 实验，采用 Skip-gram：输入中心词，预测它附近的上下文词。代码里有 80 句英文，分别涉及动物、水果、交通、自然和学习场景，最后把训练得到的词向量取出来，用余弦相似度比较不同单词。

## 先把句子变成训练词对

我先把句子转成小写并按空格分词，用 `Counter` 统计词频。`idx_to_word` 按单词首次出现的顺序保存词表，`word_to_idx` 则负责把单词转换成编号。这份语料共有 412 个词元，去重后是 77 个单词。

编号只是词表中的位置。模型真正学习的，是后面嵌入矩阵里对应的向量。

窗口大小设为 1，也就是取中心词左右各一个位置。词对构造的代码如下：

```python
for sentence in encoded_corpus:
    for center_pos,center_id in enumerate(sentence):
        #上下文窗口的左右边界
        left = max(0,center_pos - window_size)
        right = min(len(sentence),center_pos+window_size+1)

        for context_pos in range(left,right):
            if(center_pos == context_pos):
                continue
            context_id = sentence[context_pos]
            #pairs用于构建上下文和中心词词对
            pairs.append((center_id,context_id))
```

`left` 和 `right` 把窗口限制在当前句子内，`right` 是不包含在遍历范围里的右边界。遍历时跳过中心词自己的位置，剩下的位置分别生成一个 `(center_id, context_id)`。

例如 `the cat likes milk` 会产生 `cat → the` 和 `cat → likes`，也会在其他中心位置产生反向的词对。相同的词对可以在不同句子里反复出现，这些重复记录保留了共同上下文出现的次数。

对于长度为 $L$ 的句子，当前窗口会产生 $2(L-1)$ 个词对。这 80 句话合起来正好是 $2(412-80)=664$ 个，与实际输出一致。窗口固定为 1 时，构造过程随语料词元数量线性增长，保存词对也需要相应的空间。

## 词向量怎样参与预测

模型里有一张嵌入表和一个输出线性层。下面摘录初始化和前向传播部分，省略了类声明及前面的说明注释：

```python
    def __init__(self,vocab_size,embedding_dim):
        super().__init__()
        #embedding:词嵌入，负责存储和查找每一个词所对应的词向量
        self.embedding = nn.Embedding(vocab_size,embedding_dim)
        #输入一个八维的词向量，然后输出词表当中每一个单词的分数
        #这个线性层自身也有一个可训练的权重矩阵
        #bias = False表示不给这个线性层加入偏置
        self.output = nn.Linear(
            embedding_dim,vocab_size,bias = False
        )

    def forward(self,center_ids):
        #这次输入的单词所查询出来的向量
        vectors = self.embedding(center_ids)
        logits = self.output(vectors)
        return logits
```

我把词向量维度设为 8，因此嵌入表的形状是 `[77, 8]`。输入 664 个中心词编号后，查表得到 `[664, 8]` 的向量，再经过线性层得到 `[664, 77]` 的分数。每一行都对应一个训练词对，77 个分数分别对应词表中的候选上下文词。

训练标签 `targets` 保存实际上下文词的编号。`nn.CrossEntropyLoss()` 接收这些原始分数和编号，完成上下文分类的损失计算，前向传播里不用再手动加 Softmax。单个词对的目标可以写成：

$$
\ell(c,o)=-\log\frac{\exp(u_o^\mathsf{T}v_c)}{\sum_{w=1}^{V}\exp(u_w^\mathsf{T}v_c)}
$$

这里 $v_c$ 是中心词的嵌入向量，$u_w$ 是输出线性层中候选词对应的权重行。两部分参数都会参与训练，最后用于比较单词的是输入端的嵌入表。

当前实现对词表中的所有词计算分数，使用完整 Softmax，没有负采样。若词对数量是 $P$、嵌入维度是 $d$、词表大小是 $V$，输出层每轮的主要计算量为 $O(PdV)$。这次一次输入全部词对，输出分数张量需要 $O(PV)$ 的空间；77 个词的小实验可以直接这样做。

## 训练循环和实际结果

我固定随机种子为 42，使用学习率为 0.05 的 Adam，训练 30 轮。每轮都用全部词对更新一次参数：

```python
model.train()
for epoch in range(epochs):
    optimizer.zero_grad()

    logits = model(centers)
    loss = criterion(logits,targets)
    loss.backward()
    optimizer.step()
    if epoch == 0 or (epoch + 1) % 50 == 0:
        print(f"Epoch {epoch + 1:3d}, loss = {loss.item():.4f}")
```

`zero_grad()` 清掉上一轮的梯度，`backward()` 计算这轮损失对参数的梯度，`step()` 再更新嵌入表和输出层权重。

本次用项目配置的 `d2l-pytorch` 环境运行，第一轮更新前的损失为 **4.5174**。30 次参数更新完成后，额外重新计算的训练损失为 **1.9837**。这个末尾数值来自本次验证；源程序的日志条件只打印第一轮以及每 50 轮的损失，在当前 30 轮设置下不会直接打印最终损失。

训练完成后，我用 `model.embedding.weight.detach()` 取出词向量，形状是 `[77, 8]`。`detach()` 保留张量中的数据，并让后面的相似度计算脱离梯度跟踪。

## 相似度要结合语料看

代码里的 `similarity()` 从嵌入表中取出两个向量，再用 `F.cosine_similarity(..., dim=0)` 比较它们的方向：

$$
\operatorname{cos}(a,b)=\frac{a^\mathsf{T}b}{\lVert a\rVert\lVert b\rVert}
$$

测试里既有同类词，也有不同类别的词和单词自身。下面是本次运行的部分结果，保留四位小数：

| 对照 | 单词一 | 单词二 | 余弦相似度 |
| --- | --- | --- | ---: |
| 动物 | cat | dog | 0.8164 |
| 水果 | apple | orange | 0.6987 |
| 水果 | apple | banana | 0.7843 |
| 交通 | car | bus | 0.7452 |
| 人物 | student | teacher | 0.7886 |
| 自然 | sun | moon | 0.8894 |
| 不同类别 | cat | car | 0.3438 |
| 不同类别 | apple | bus | 0.6057 |
| 单词自身 | cat | cat | 1.0000 |

`cat` 和 `dog` 在语料里多次共享 `likes milk`、`drinks water` 等句子结构，`sun` 和 `moon` 也共享 `shines in the sky`、`rises above the mountain`。这些对照在本次训练中得到较高的相似度，符合语料设计的预期。

不过，`apple` 和 `bus` 的相似度也有 0.6057。语料只有 80 句话，又反复使用 `the`、`is`、`in` 等词，窗口还只有 1；这些分数需要放在具体语料里解释。训练损失下降能说明模型在拟合上下文预测任务，不能据此认定它已经学好了普遍的语义关系。

这份代码把词表、训练词对、上下文预测和词向量比较连了起来。后面若要继续观察词向量的变化，可以固定其余条件，分别改变窗口大小、训练轮数或语料，再比较同一组词对的分数。
