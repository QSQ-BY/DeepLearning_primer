这次我按chatgpt老师六课的顺序学习了 TextCNN，再把各层接成一个中文评论情感分类的小实验。全连接层、Softmax 和交叉熵之前已经学过，所以这篇主要记录文本怎样变成卷积输入、卷积核在文本上怎样移动，以及池化和变长句子的处理。

代码也按这个过程分成了三部分：`test01()` 分别验证各层和手算结果，`test02()` 串起完整的模型定义到前向传播并调用反向传播，`test03()` 加入数据处理、训练和验证，进行一次完整规模的训练。

## 词编号用来查表，词向量才参与后面的计算

输入一句话，先分词，再把每个词换成词表里的编号。编号只是索引，不能拿它的大小解释词义。Embedding 根据编号，从形状为 $[V,D]$ 的权重矩阵里取出对应的行；$V$ 是词表大小，$D$ 是每个词的向量维度。

这和之前 Word2Vec 里的嵌入表能接起来看。不过，这次 TextCNN 没有加载之前训练的词向量，而是重新随机初始化，让词向量随着情感分类损失一起更新。查表这个动作本身很简单，表里的数值如何调整，取决于后面的任务。

一批句子的编号张量是 $[B,L]$，查表后变成 $[B,L,D]$。`test01()` 设置词表大小为 1000、词向量维度为 128，输入形状为 `[32,50]`，实际得到的输出就是 `[32,50,128]`。批量大小和句子长度都不会改变嵌入表自身的大小。

当前完整实验用空格分隔中文词语，例如 `这部 电影 真的 很 好看`。`encode()` 里的 `split()` 只按空白切分，不负责中文分词。直接输入没有空格的整句话，会把它当成一个词，再映射成 `<UNK>`。

## 卷积沿词序滑动，词向量维度对应输入通道

文本经过 Embedding 后，每一行对应一个词。一个覆盖两个词的卷积核，会依次处理第 1、2 个词，第 2、3 个词，再到第 3、4 个词。窗口里的词向量与权重逐项相乘、求和，再加上偏置，就得到这个位置的响应。

我用代码里的小矩阵对照这个过程：

$$
H=\begin{bmatrix}
0.2&0.5&-0.1\\
0.6&-0.3&0.8\\
0.1&0.7&0.4\\
0.9&0.2&0.6
\end{bmatrix},\qquad
W=\begin{bmatrix}
1&0&-1\\
0&1&1
\end{bmatrix},\qquad b=-0.7
$$

第一个窗口覆盖前两行，计算得到：

$$
z_1=0.2\times1+0.5\times0+(-0.1)\times(-1)
+0.6\times0+(-0.3)\times1+0.8\times1-0.7=0.1
$$

沿词序移动后，三个位置的结果是 `[0.1,0.2,-0.2]`，经过 ReLU 后变成 `[0.1,0.2,0.0]`，与实际运行一致。同一个卷积核在所有窗口共享权重；它输出一整条特征图，而不是只给整句话输出一个数。

落实到 `Conv1d`，需要先把 Embedding 输出从 $[B,L,D]$ 转成 $[B,D,L]$。这里 $D$ 是输入通道数，卷积核沿最后的序列维度移动。对每个输出通道，它会同时使用全部 $D$ 个输入通道的信息。

完整模型中，Embedding 和多尺度卷积层的定义如下，省略了初始化方法中的其余部分：

```python
self.embedding = nn.Embedding(
    num_embeddings=vocab_size,#整个词表的单词总数
    embedding_dim=EMBED_DIM,
    padding_idx=PAD_ID
)

self.convs = nn.ModuleList([
    nn.Conv1d(
        in_channels=EMBED_DIM,
        out_channels=NUM_FILTERS,
        kernel_size=k
    )
    for k in KERNEL_SIZES
])
```

这段代码把三个设置分开了：`EMBED_DIM` 决定每个词有多少维，`NUM_FILTERS` 决定每种窗口宽度生成多少条特征图，`kernel_size` 决定窗口覆盖几个词。词向量维度与输出通道数可以独立设置，即使本次都取 32，含义也不同。

PyTorch 保存的卷积权重形状是 $[F,D,k]$。手算时按“两个词、每词三维”写成的 $[k,D]$ 矩阵，在单个 `Conv1d` 卷积核里按 $[D,k]$ 排列。因此 `test01()` 给权重赋值时，每一行对应一个输入通道在两个词位置上的权重。

用 `Conv2d` 也能表达同一种文本卷积：输入为 $[B,1,L,D]$，卷积核大小为 $(k,D)$，宽度一次覆盖整个词向量。两种写法的输入排列不同，都在提取相邻词语的组合特征。

## 最大池化把不同长度的特征图变成固定长度

卷积之后，一条特征图记录同一个卷积核在不同位置的响应。Max-over-time Pooling 沿序列方向取最大值，每条特征图只留下一个数。

`test01()` 中三条特征图分别是 `[0.1,0.2,0.0]`、`[0.6,0.6,1.5]`、`[0.4,0.0,0.8]`，池化后得到 `[0.2,1.5,0.8]`。这三个数分别属于三个输出通道，不能沿通道维把它们再压成一个数。

下面是 `test02()` 中对每组卷积做激活和池化的部分，循环前后的代码未列出：

```python
for conv in self.convs:

    feature = F.relu(conv(x))
    # feature: (B, F, L-k+1)

    pooled = F.adaptive_max_pool1d(
        feature,
        output_size=1
    )
    # pooled: (B, F, 1)

    pooled = pooled.squeeze(-1)
    # pooled: (B, F)

    pooled_outputs.append(pooled)
```

`output_size=1` 把每条特征图沿长度方向压到一个位置，随后 `squeeze(-1)` 只移除这个长度为 1 的维度，保留批量和通道。每组得到的结果都是 $[B,F]$，接着才能沿特征维拼接。

卷积核宽度为 2、3、4 时，卷积输出的长度分别是 $L-1$、$L-2$、$L-3$。这些长度原本不同，池化后却都变成 $[B,F]$。这也解释了为什么不同尺度的分支可以接到一起。

完整训练版本每种宽度用 32 个输出通道，三个分支拼接后，每句话有 $32\times3=96$ 个特征。一次批量输入的形状变化是：

| 处理位置 | 形状 |
| --- | --- |
| 词编号 | `[16,L]` |
| Embedding 输出 | `[16,L,32]` |
| 转成卷积输入 | `[16,32,L]` |
| 宽度为 2、3、4 的卷积输出 | `[16,32,L-1]`、`[16,32,L-2]`、`[16,32,L-3]` |
| 每个分支池化后 | `[16,32]` |
| 三个分支拼接后 | `[16,96]` |
| 分类分数 | `[16,2]` |

卷积保留了窗口内部的词序，例如“不 值得 推荐”和“值得 推荐”可能产生不同的响应。但最大池化只保留响应强度，不再记录最大值来自句子的哪个位置。句子表示变得紧凑，也丢掉了这部分位置信息。

## 分类和损失接在句子特征后面

后面接回已经学过的分类流程：96 维特征经过 Dropout 和线性层，得到消极、积极两个 logits。训练时直接将 logits 和类别编号交给 `F.cross_entropy()`，展示概率时再使用 Softmax。

基础演示的线性层输出 `[1,2]`，积极类别的概率约为 `0.7311`，标签为 1 时损失约为 `0.3133`。这部分用于核对接口和数值，不再展开重复推导。

## 补齐句子之后，还要限制哪些窗口参与池化

变长句子组成一个批次时，需要先补成相同长度。`collate_fn()` 会返回补齐后的 `input_ids`、每句话补齐前的 `lengths`，以及标签。补齐长度还至少要达到最大卷积核宽度 4，否则短句无法通过较宽的卷积层。

`padding_idx=PAD_ID` 指定的是嵌入表里的填充项，当前初始化和训练方式下这一行保持为零。真正把 PAD 编号填进句子的是 `collate_fn()`。

即使 PAD 向量是零，卷积也不会自动跳过填充位置。窗口可能只包含部分真实词语，还可能因偏置产生响应。要让池化结果对应预定的有效窗口，还需要根据真实长度创建掩码。

对于真实长度为 $\ell$、卷积核宽度为 $k$ 的句子，完全落在真实文本内的窗口有 $\max(\ell-k+1,0)$ 个。例如句长为 4、核宽为 3，只应保留从位置 0、1 开始的两个完整窗口，不能因为同批次里有更长的句子就增加有效窗口。

完整模型的掩码和池化代码如下，仅省略空行：

```python
valid_count = (
    lengths - kernel_size + 1
).clamp(min=1)
positions = torch.arange(
    feature.size(-1),
    device=feature.device
).unsqueeze(0)
mask = (
    positions < valid_count.unsqueeze(1)
)
# 忽略无效 Padding 窗口
feature = feature.masked_fill(
    ~mask.unsqueeze(1),
    float("-inf")
)
# 全局最大池化：(B, F)
pooled = feature.amax(dim=-1)
```

`positions` 保存卷积输出的位置编号，与每句话的 `valid_count` 比较后得到 $[B,L_{out}]$ 的掩码。`unsqueeze(1)` 增加通道维，同一句话的所有输出通道就可以共用这个位置限制。无效响应填成负无穷，随后沿最后一维取最大值。

这里的 `clamp(min=1)` 还规定了短句的处理方式：真实长度小于核宽时，保留第一个补零后的窗口，避免全部屏蔽后得到负无穷。这时保留的窗口含有 PAD，不能再称为完全落在真实文本内的窗口。当前教学训练样本都至少有 4 个词，这个分支主要照顾更短的预测输入。

## 把数据处理接到训练循环

实验用 8 种主语组合搭配正、负各 10 种情感模板，生成 160 条评论，再按类别分别划分出 128 条训练样本和 32 条验证样本。词表只从训练集统计，包含 `<PAD>` 和 `<UNK>`，实际大小为 43。

`ReviewDataset` 保存编码后的单条样本，`DataLoader` 按批量取出它们，再由 `collate_fn()` 补齐。训练集每轮打乱顺序，批量大小为 16，每轮做 8 次参数更新。12 轮合计更新 96 次。

完整模型使用 32 维词向量、三组宽度为 2、3、4 的卷积、`Dropout(0.3)`，以及学习率为 `0.003` 的 Adam。`nn.ModuleList` 负责注册各个卷积分支，让这些参数能被优化器取得并更新。

训练循环仍是清空梯度、前向传播、计算损失、反向传播、更新参数。验证时使用 `model.eval()` 关闭 Dropout 的随机丢弃，并用 `torch.no_grad()` 关闭梯度记录。两者负责的事情不同，切换到评估模式不会自动关闭自动求导。

我现在可以沿着一条句子的形状变化检查 TextCNN：词编号查出词向量，卷积提取局部组合，池化汇总各个通道的响应，最后得到固定长度的句子特征。换成真实评论时，还需要先统一分词方式，再用未见过的句式检验这些局部特征是否仍然有用。
