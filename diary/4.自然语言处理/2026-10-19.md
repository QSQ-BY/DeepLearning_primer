这次我从零开始学习循环神经网络。最先理解的是上下文的作用：读到“好”时，前面是“很”还是“并不”，会改变整句话的意思。词向量求平均会丢掉排列顺序，而 RNN 通过逐步更新隐藏状态，让前面的输入参与后面的计算。

我先用简单的数字递推理解状态传递，再用 PyTorch 做字符级的下一个字符预测。写代码时，光知道“当前输入加上旧状态”还不够：输入为什么有时间维度？RNN 返回的两个张量有什么区别？这些问题需要对着实际的张量形状一点点弄清楚。

## 隐藏状态沿序列传递，参数在时间步之间共享

最开始用的简化规则是：

$$
h_t=0.5h_{t-1}+x_t,\qquad h_0=0
$$

输入依次为 $2,4,1$ 时，状态依次是 $2,5,3.5$。把第一个输入改成 $6$，状态就变成 $6,7,4.5$。展开最后一步可以看到：

$$
h_3=0.25x_1+0.5x_2+x_3
$$

沿着 $x_1\to h_1\to h_2\to h_3$，第一个输入确实能影响最后的状态。我起初以为前面的每个词都会这样影响后面的处理，但展开后，第一个输入的系数已经衰减到了 $0.25$。信息能传下来，影响也可能越来越弱，不能据此认为模型完整记住了前文。

普通 RNN 把这个规则扩展成可训练的计算：

$$
h_t=\tanh(W_xx_t+W_hh_{t-1}+b)
$$

这里采用列向量写法。输入维度为 $d$、隐藏维度为 $h$ 时，$W_x$ 是 $(h,d)$，$W_h$ 是 $(h,h)$。例如输入有 4 维、隐藏状态有 3 维，两组矩阵就是 $(3,4)$ 和 $(3,3)$。

我需要分清参数和状态：序列变长，会多做几次状态更新，但不会为新增的时间步创建新的权重。上式把偏置合写成了一个 $b$；PyTorch 的 `nn.RNN` 实际分别保存输入侧和隐藏侧的偏置。它们同样在时间步之间共享。

## 时间步是序列的位置

一开始我没弄清时间步是什么，也不明白输入里为什么要包含它。按字符处理文本时，一个字符就是一个时间步。输入张量需要保存一批序列，每条序列又有多个字符，因此会有单独的时间维度。这个维度用来排列字符向量，不是给每个字符额外增加一个“时间”特征。

当前代码把 `"hello pytorch\n"` 重复 100 次作为语料，得到 11 种字符。`batch_size` 和 `num_steps` 都是 16，隐藏维度是 32。一次采样的代码是：

```python
def get_batch():
    #随机选取16段序列，每段包含16个时间步
    starts = torch.randint(len(data)-num_steps,(batch_size,))
    positions = starts[:,None] + torch.arange(num_steps)

    X = data[positions]
    Y = data[positions+1]
    return X,Y
```

`starts` 保存 16 个随机起点。`starts[:,None]` 的形状为 `[16,1]`，与长度为 16 的偏移相加，通过广播形成 `[16,16]` 的下标矩阵，每一行对应一段连续文本。

`Y` 的下标比 `X` 多 1，所以每个位置都在预测下一个字符。起点最大为 `len(data)-num_steps-1`，这样标签的最后一个下标仍不会越界。构造这些下标和样本的时间、空间开销都是 $O(BT)$，这里 $B$ 是批量大小，$T$ 是每段的时间步数。

时间维保存字符向量的先后顺序。RNN 在第 $t$ 步取出所有样本当前位置的输入，单步输入形状是 `[B,V]`，其中 $V$ 是 one-hot 向量的长度。同一批里的不同样本各自维护状态，不会把上一行文本的状态传给下一行。

## RNN 输出隐藏特征，再由线性层预测字符

代码用 `nn.RNN(input_size=vocab_size, hidden_size=hidden_size, batch_first=True)` 定义循环层，再用 `nn.Linear(hidden_size,vocab_size)` 产生字符分数。默认是一层、单向、使用 `tanh` 的 RNN。

当前实现的形状依次是：

| 内容 | 形状 | 含义 |
| --- | --- | --- |
| 字符编号 `X`、`Y` | `[16,16]` | 16 段文本，每段 16 个字符 |
| one-hot 输入 | `[16,16,11]` | 每个字符转换成 11 维向量 |
| RNN 的序列输出 `H` | `[16,16,32]` | 每个时间步的隐藏特征 |
| 最终隐藏状态 `h_last` | `[1,16,32]` | 每层、每个样本的最后状态 |
| 字符分数 `logits` | `[16,16,11]` | 每个位置对下一个字符的分数 |

看到 RNN 返回 `H` 和 `h_last` 时，我需要先分清它们各自保存了什么。对于这里的单层、单向 RNN，`H[:, -1, :]` 和 `h_last[0]` 对应相同的最终状态；`H` 还保留了前面所有位置的状态。`batch_first=True` 调整的是输入和序列输出的排列，最终状态仍把层与方向放在第一维。

每个位置都需要预测下一个字符，所以代码把整个 `H` 交给线性层。`nn.Linear` 只变换最后一维，将每个位置的 32 个隐藏特征映射成 11 个字符分数。隐藏维度和类别数量可以分别设置。

## BPTT 沿时间依赖求梯度，裁剪放在更新之前

既然早期的 $h_1$ 会一路影响最后的输出，那么反向传播时，梯度也应该从后面的状态一路传回 $h_1$。顺着前向计算的依赖关系，我理解了 BPTT，也就是沿时间展开的反向传播。PyTorch 会记录循环层内部的计算关系，调用 `loss.backward()` 时自动沿这些关系求导。

下面摘录 RNN 训练循环中从取样到裁剪的部分；循环声明和后续的 `optimizer.step()`、打印语句未列出：

```python
    X,Y = get_batch()
    optimizer.zero_grad()
    logits,h_last = model(X)
    #把batch和时间维度展开：每个时间步都是一次字符分类
    loss = criterion(logits.reshape(-1,vocab_size),Y.reshape(-1))
    #BPTT:沿展开的时间链路反向传播
    loss.backward()

    grad_norm = nn.utils.clip_grad_norm_(
        model.parameters(),
        max_norm = 1.0,
    )
```

这里有 256 个字符分类位置，分数展开为 `[256,11]`，标签展开为 `[256]`。两者按同样的顺序展平，仍能一一对应。循环层已经处理过时间关系，在损失计算前展平不会抹掉这段计算图。

我也重新区分了几个操作：`zero_grad()` 清掉旧梯度，`backward()` 计算梯度，梯度裁剪限制梯度范数，最后由 `optimizer.step()` 更新参数。执行完反向传播，权重还没有更新。

梯度沿时间传递时会出现导数连乘，过多的小因子可能让梯度消失，过多的大因子可能让梯度爆炸。用一个简化例子就能看出来：每步放大 2 倍，20 步后就是 $2^{20}$ 倍。真实 RNN 还涉及矩阵和激活函数的导数，但连乘带来的问题仍在。

范数裁剪把所有参与参数的梯度合起来看，超过阈值时按同一比例缩小，保留整体方向。例如梯度 $(3,4)$ 的范数为 5，裁剪到阈值 1 后成为 $(0.6,0.8)$；范数只有 0.5 时则保持原值。这和逐个分量截断不同，也不能用来解决梯度消失。

当前每段序列有 16 个时间步，调用循环层时没有传入初始状态，因此每个随机批次都从零状态开始。BPTT 覆盖的是各段内部的 16 步依赖；前一批返回的 `h_last` 没有接到下一批。这与独立随机片段的采样方式一致。

## LSTM 把记忆的保留、写入和输出分开

学习 LSTM 时，我从“某些信息后面还会用到，应该先保存下来”理解细胞状态 $c_t$。标准 LSTM 用门控决定各个分量保留多少旧内容、写入多少新内容：

$$
c_t=f_t\odot c_{t-1}+i_t\odot\widetilde c_t
$$

$$
h_t=o_t\odot\tanh(c_t)
$$

遗忘门 $f_t$ 控制旧记忆的保留比例，输入门 $i_t$ 控制候选记忆 $\widetilde c_t$ 的写入比例，输出门 $o_t$ 控制当前隐藏状态的形成。门使用 sigmoid 产生 0 到 1 之间的比例，候选记忆使用 `tanh`，可以为正或负。

如果希望某个分量暂时保留原来的内容，可以让遗忘门接近 1、输入门接近 0。沿细胞状态的直接传递路径，梯度也更容易保留下来。不过，这只是完整计算图中的一条路径，LSTM 仍不能保证所有长期信息都不丢失。

每个时间步的门值不一样，是不是意味着每一步都有单独训练的参数？我最初把这两件事混在了一起。实际上，同一种门在不同时间步共享权重和偏置；当前输入与上一隐藏状态改变，算出的门值就可能改变。门值变化不等于权重刚刚更新了。不同种类的门则各有自己的参数。

输出门也不直接修改本步已经算好的 $c_t$，但它产生的 $h_t$ 会参与下一步门控的计算，因此仍可能间接影响后续记忆。

当前 `CharLSTM` 的前向传播如下，初始化部分未列出：

```python
    def forward(self,X):
        #字符编号->one_hot 浮点向量
        X = F.one_hot(X,num_classes = vocab_size).float()
        H,(h_last,c_last) = self.lstm(X)
        logits = self.output(H)
        return logits,(h_last,c_last)
```

它保留了与 RNN 相同的数据和输出层结构，只把循环层换成 LSTM。`H` 仍是所有时间步的隐藏状态，返回的最终状态则多了 `c_last`。在当前单层、单向设置下，`h_last` 和 `c_last` 都是 `[1,16,32]`，输出分数仍是 `[16,16,11]`。

## 接到新闻分类时，还要处理双向状态和填充

接到 BiLSTM 新闻分类时，我又在分类层的维度上卡了一下：双向状态拼接后，还需要把批量大小乘进去吗？每个方向的隐藏维度为 64，拼接后每条新闻有 128 个特征。四分类线性层的权重形状为 `[4,128]`；批量大小为 32 时，输入特征为 `[32,128]`，输出分数为 `[32,4]`。批量大小只表示同时处理多少条新闻，每条新闻仍然只有 128 个特征。

取状态时也要注意方向。对于单层双向 LSTM，可以拼接 `h_n` 中两个方向的最终状态；逆向读完整条序列的状态对应原序列的第一个位置，所以直接取 `output[:, -1, :]`，并不能同时拿到两个方向读完整条序列后的状态。

填充为零也不会自动让循环层停止更新。即使当前输入是零，旧状态和偏置仍参与计算，因此需要按真实长度处理尾部 PAD。`pack_padded_sequence` 根据 `lengths` 决定有效位置，`padding_idx` 只管理 Embedding 的填充项，不能替代序列打包。

我还区分了 logits、概率与损失：线性层输出原始分数；展示概率时可以做 Softmax；训练时把 logits 和真实类别编号直接交给 `CrossEntropyLoss`，得到的是损失。

当前项目落地的是字符级 RNN 和 LSTM 小实验。BiLSTM 分类、变长序列打包，以及与其他新闻分类模型的对照，还需要在后续实现中验证。到那一步，我会沿着词编号、词向量、有效长度、双向状态和类别分数逐层核对形状。
