# 从多层感知机到自己的训练闭环

> 日期：2026 年 8 月 25 日至 8 月 30 日
> 学习资料：[《动手学习深度学习（PyTorch 版本）》](https://tangshusen.me/Dive-into-DL-PyTorch/)

这几天，我完成了多层感知机的手写版和简洁版，也让自己的 NumPy 神经网络框架第一次跑通了训练。对我这个刚入门的新手来说，我真正想记下来的，是自己怎样跟着 AI 老师把一个完全不知道该从哪里下手的任务，一步步拆成能理解、能测试、最后也真的能训练的小项目。

## 一开始，我只想着把公式写出来

刚开始做这个框架时，我对“实现神经网络”的理解还很直接：把矩阵乘法写出来，再补上反向传播，应该就差不多了。真正面对项目时，我才发现自己连第一步该建哪些文件都不清楚。一个框架除了层，还需要怎样保存参数和梯度，损失函数怎样把梯度交回网络，优化器又怎样找到需要修改的数组，这些问题以前都被 PyTorch 藏起来了。

AI 老师先带我把大任务缩小。卷积层和 Batch Normalization 被放到后面，眼前的最小目标只有一个：只用 NumPy，完成 `Linear → ReLU → Linear` 的前向传播、反向传播和参数更新。项目里先有了 `mininn` 包、`tests`、`examples` 和设计文档，再从最基础的 `Linear` 开始。

这个过程让我第一次体会到，项目骨架会提前决定代码放在哪里、组件怎样连接，也会逼着我想清楚每一部分究竟负责什么。AI 老师把任务拆得很小，我的注意力也跟着落到眼前能够验证的一步上，不再对着“做一个神经网络框架”这个大目标发愣。

## AI 老师先让我学会写失败的测试

我原本以为写 `Linear.forward()` 的重点就是 `x @ weight + bias`。AI 老师却一直追问：如果输入不是二维数组怎么办？特征数量对不上怎么办？调用者应该看到什么异常？这些问题一开始让我有些意外，因为它们看起来离神经网络公式很远。

我们先把预期行为写进测试，再去补实现。例如，测试会故意送入错误形状的数据：

```python
layer = layers.Linear(2,3,rng = np.random.default_rng(7))
#故意创建错误的输入
wrong_x = np.ones((4,5))
try:
    layer.forward(wrong_x)
#在forward函数已经抛出了ValueError的时候触发
except ValueError as error:
    self.assertIn(
        "expected 2 input features",
        str(error),
    )
else:
    self.fail(
        "Linear.forward() should reject the wrong feature count"
    )
```

以前我对测试的理解更接近“运行一下，看看有没有报错”。跟着 AI 老师写完这段后，我才知道测试还要区分异常类型、检查错误信息，并确认本来应该失败的输入没有被悄悄接受。测试会先把接口应该怎样工作写清楚，失败结果再告诉我目前还缺什么。

这种顺序后来贯穿了整个框架：先写一个会失败的测试，运行并读懂失败原因，再补刚好能让它通过的实现。对新手来说，这种做法反而让我更踏实。任务再小，也有明确的完成标准；代码改坏了，原来通过的测试也会马上提醒我。

## 反向传播从书上的式子落进代码

到了 `Linear.backward()`，我第一次真正把链式法则放进一层网络里。前向传播是

\[
Y=XW+b
\]

反向传播要分别得到输入、权重和偏置的梯度：

\[
\frac{\partial L}{\partial X}=GW^\mathsf T,
\qquad
\frac{\partial L}{\partial W}=X^\mathsf TG,
\qquad
\frac{\partial L}{\partial b}=\sum_{\text{batch}}G
\]

我当时反复问 AI 老师，为什么对输出的梯度乘上权重转置，就会变成对输入的梯度。把矩阵拆成元素并沿着链式法则重新看以后，我才明白转置负责汇总一个输入特征对所有输出方向造成的影响，正确的形状只是这个推导的结果。

实现这三个公式还不够。前向传播必须缓存输入，否则反向传播算不出 `X.T @ grad_output`；`backward()` 必须检查有没有先执行 `forward()`；参数与梯度还要按相同顺序返回，并且保持原数组引用，后面的 SGD 才能真正改到模型里的权重。

AI 老师又带我用有限差分检查解析梯度。我以前看到测试通过就容易放心，但有限差分走的是另一条计算路径：轻微改变某个权重，观察标量损失怎样变化，再和反向传播算出的梯度比较。13 项 `Linear` 测试全部通过时，我得到了一层可以运行的代码，也第一次知道该怎样为数学实现寻找独立证据。

## 先回到多层感知机，把 ReLU 学明白

完成 `Linear` 反向传播后，我先回到《动手学深度学习》的主线，把 ReLU 的原理补清楚。AI 老师提醒我，项目下一步正好要做激活函数，如果只知道 `maximum(0, x)` 这一行，很容易写完代码却不知道它为什么存在。

手写多层感知机时，我把 Fashion-MNIST 图片展平成 784 维向量，用 256 个隐藏单元连接到 10 个类别：

```python
def relu(X):
    return torch.max(input = X,other = torch.tensor(0.0))

#定义模型
def net(X):
    X = X.view((-1,num_inputs))
    H = relu(torch.matmul(X,w1) + b1)
    return torch.matmul(H,w2) + b2
```

第一层把 784 维输入映射到 256 维，ReLU 把非正数变成 0，第二层再输出 10 个类别分数。如果中间没有 ReLU，两个线性层最终仍然能合并成一个线性变换，隐藏层再宽也没有增加新的表达能力。

我随后又用 `nn.Sequential` 写了简洁版本。以前看到 `nn.Linear`、`nn.ReLU` 和 `nn.Sequential`，我只把它们当成方便调用的 API；这一次，手写模型和自制框架正好对上了。PyTorch 已经替我处理的参数注册、前向调用顺序和梯度保存，都是自己的框架接下来必须解决的问题。

## 回到框架，每个组件都有了位置

理解多层感知机后，我再跟着 AI 老师回到 NumPy 框架，ReLU 就不再是一行孤零零的取最大值操作。它在前向传播时保存正值掩码，反向传播时只让对应位置的梯度通过；它没有可训练参数，却仍然返回空的参数和梯度列表，让 `Sequential` 可以用同一种方式处理所有层。

Softmax 交叉熵还要考虑数值稳定。为了避免指数溢出，每个样本的 logits 要先减去该行最大值。这个变化不会改变 Softmax 概率，却能把数值控制在安全范围内。反向传播返回 `(probabilities - one_hot(labels)) / batch_size`，它正好是网络最后一层需要接住的梯度。

接着是 `Sequential`。前向传播按保存顺序调用每一层，反向传播则必须倒过来走。最后的 SGD 看起来最短，只做 `parameter -= learning_rate * gradient`，但它依赖前面已经约定好的参数顺序、梯度顺序和数组引用。做到这里时，我才慢慢看见：这些类不是各自算完一个公式就结束了，它们之间一直在传递数据和约定。

这几天的提交顺序也记录了我的学习顺序：ReLU、稳定的 Softmax 交叉熵、`Sequential`、SGD。AI 老师每次只带我处理一个组件，我先用测试把行为说清楚，再写实现，最后回头检查它能不能和已有组件接在一起。框架就是这样一点点长出来的。

## 从 13 项测试走到真正的训练闭环

单个组件通过测试以后，我们又加了组合测试和端到端训练测试。最后的玩具网络是 `Linear(2, 16) → ReLU → Linear(16, 3)`，完整训练循环只剩四步：

```python
for epoch in range(301):
    logits = network.forward(features)
    loss_value = loss_function.forward(logits, labels)
    network.backward(loss_function.backward())
    optimizer.step()
```

现在我能沿着这几行代码把整个过程讲出来：网络先算出 logits，损失函数保存概率和标签；损失函数产生对 logits 的梯度，`Sequential` 再让梯度依次经过第二个 `Linear`、ReLU 和第一个 `Linear`；两个线性层写入四组参数梯度，SGD 最后原地更新权重和偏置。下一轮前向传播读到新参数，训练才真正形成闭环。

测试从最初检查一个 `Linear`，逐渐增加到 50 项，覆盖数值计算、错误输入、调用顺序、有限差分、参数收集、优化器更新和端到端训练。玩具分类器从第 0 轮的 `loss=1.268683`、`accuracy=34.00%`，训练到第 300 轮时的 `loss=0.013734`、`accuracy=99.67%`。

看到损失真的下降时，我才有一种“前面那些零散东西终于接起来了”的实感。对熟悉框架的人来说，这可能只是一个很小的分类器；对刚入门的我来说，它证明我写的前向传播、梯度和参数更新确实能够互相配合。50 个绿色的测试结果记录了我从只会看正常输入，到开始主动考虑边界、调用顺序和独立验证的过程。

## 这次跟着 AI，我学到了一套做项目的方法

回头看整个过程，AI 老师一直在帮我缩小问题：这一层的接口是什么，错误输入应该怎样失败，梯度为什么这样算，这个测试究竟证明了什么。我负责把代码一行行写出来，运行失败测试，追问自己没有想通的地方，再把新的理解放回实现里。

我现在仍然是刚开始学深度学习的小白。这个框架完成的也只是最小训练闭环，卷积层和 Batch Normalization 还没有实现。但我看待框架的方式已经变了。以前我记住的是 `loss.backward()` 和 `optimizer.step()` 这两个调用；现在看到它们，我会想到背后的缓存、梯度流、参数引用和更新顺序。

下一次继续扩展框架时，我仍然会遇到很多不懂的地方。不过我已经有了一条可以重复使用的学习路径：先和 AI 老师把任务拆小，弄清接口和数学原理，用测试写下预期，再实现并找独立证据验证。对现在的我来说，这套走法比记住某一个 API 更重要。
