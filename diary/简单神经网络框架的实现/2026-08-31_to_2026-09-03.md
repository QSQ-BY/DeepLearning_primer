## 卷积没有新运算，难点却一下子多了

真正写过一遍以后，我发现卷积层和线性层在运算本身上确实没有特别本质的区别。线性层计算矩阵乘法，卷积层则取出一个局部窗口，让窗口中的值与卷积核对应相乘，再把结果相加。除去偏置以后，它们都是线性变换；加上偏置后则是仿射变换。这里没有突然冒出乘方、指数或者对数，核心仍然只是加法和乘法。

区别主要在结构。`Linear` 会让每个输入特征连接每个输出特征，卷积层只观察局部区域，并让同一个卷积核在不同空间位置重复使用。也正因为如此，卷积层的维度和索引比线性层麻烦得多。输入通常写成：

\[
X\in\mathbb{R}^{N\times C_{in}\times H\times W}
\]

这四个维度分别是样本数、输入通道数、高度和宽度。卷积核还要再增加输出通道这一层关系。写前向传播时，我必须同时弄清楚当前正在处理哪个样本、哪个输出通道，以及卷积核落在输出特征图的哪一行、哪一列。

实际代码中的核心循环是：

```python
for batch_index in range(batch_size):
    for output_channel in range(self.out_channels):
        for output_row in range(output_height):
            for output_column in range(output_width):
                row_start = output_row * self.stride
                row_end = row_start + self.kernel_size
                column_start = output_column * self.stride
                column_end = column_start + self.kernel_size
                # 从输入中截取卷积核当前覆盖的窗口
                input_window = padded_x[batch_index,:,row_start:row_end,column_start:column_end]

                # 取出对应的输出通道的卷积核
                kernel = self.weight[output_channel]

                #进行卷积的计算
                output[batch_index,output_channel,output_row,output_column] = (np.sum(kernel * input_window) + self.bias[output_channel])
```

最里面的一行并不难：`kernel * input_window` 对应位置相乘，`np.sum()` 把输入通道和卷积核高、宽三个维度全部求和，最后加上当前输出通道的偏置。困难的是到达这一行之前，必须保证四层循环、步幅换算、窗口边界和各个数组的形状全都对应正确。只要某一层下标想错，程序仍然可能运行，却会算出另一件东西。

`padding` 也让我重新认识了 NumPy 的维度表达。NCHW 输入只需要扩展高度和宽度，样本与通道不能改变，因此 `pad_width` 必须按四个维度逐一说明：N、C 两侧都填充 0，H、W 两侧才填入 `padding`。原先一句“在输入周围补零”，写成代码以后就必须精确到每一个轴。

## 反向传播最让我痛苦的地方

我自认为高等数学和线性代数的基础还算扎实，但推卷积层的多重导数时还是很吃力。纸上的链式法则是熟悉的，真正的问题是怎样把它和 NCHW 的各个维度、卷积核共享、窗口重叠结合起来，最后再翻译成一层层循环和切片。这个过程经常让我在同一处想很久，脑子里知道“这里应该按链式法则传回去”，却一时无法确定这个量究竟该写进数组的哪个位置。

一次前向计算可以写成：

\[
y_{n,o,h,w}
=\sum_{c,i,j}x_{n,c,h_s+i,w_s+j}W_{o,c,i,j}+b_o
\]

反向传播收到的上游梯度，是损失对这个输出位置的导数：

\[
g_{n,o,h,w}=\frac{\partial L}{\partial y_{n,o,h,w}}
\]

它在代码里不是单独完成某一种计算，而是同时参与两条链式求导路径：输入窗口乘上它，累加到当前输出通道的卷积核梯度；当前卷积核乘上它，累加回这次窗口覆盖的输入区域。

```python
gradient = grad_output[
    batch_index,
    output_channel,
    output_row,
    output_column,
]
self.grad_weight[output_channel] += input_window * gradient
grad_padded_input[
    batch_index,
    :,
    row_start:row_end,
    column_start:column_end,
] += self.weight[output_channel] * gradient
```

这里的 `+=` 很重要。同一块输入可能被多个相邻窗口反复覆盖，同一个卷积核也会被所有样本和所有输出位置重复使用，所以它们对损失的影响必须累加。偏置梯度也是同样的道理：每个输出通道只有一个偏置，因此要把该通道在所有样本、所有高度和所有宽度位置上的上游梯度加起来：

\[
\frac{\partial L}{\partial b_o}
=\sum_{n,h,w}g_{n,o,h,w}
\]

对应到 NumPy，就是 `grad_output.sum(axis=(0, 2, 3))`。求和后只留下输出通道这一维。

这几天最强烈的感受是：理解一个公式和把它写成可靠代码，中间隔着很长一段路。低维情况下，我还能很快在纸上追踪每个变量；一进入 NCHW，再叠加输出通道、步幅、填充和重叠窗口，脑中的图像就很容易散掉。TDD 在这里给了我一个可以落脚的顺序。我不需要一次把整个卷积层都想清楚，而是先处理最小的单通道例子，再扩展到多样本、多输入通道和多输出通道，最后分别检查偏置、卷积核和输入梯度。

下一步的 `Flatten` 在数学上会轻松不少。它不改变数值，只记录输入形状，把每个样本的 `(C,H,W)` 展开成一个向量，反向传播时再恢复原形。等它接到卷积层与线性层之间，我就可以第一次用自己写的组件搭出完整的卷积网络。到那时，这几天反复推导的四维梯度才会真正进入一次从输入到损失、再从损失返回参数的训练过程。
