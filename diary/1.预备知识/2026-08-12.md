## 正式学完数据处理

今天算是正式学完了数据处理这一节。内容不算多，主要是一些不太常见的 Tensor 操作：怎样减少不必要的内存开销、Tensor 和 NumPy 之间转换时数据是否共享，以及怎样把 Tensor 放到 GPU 上。

这些写法单独看有些零碎，也不像创建 Tensor、索引和广播那样一眼就能看出用途。不过把它们实际敲过一遍之后，我对 Tensor 背后的数据关系清楚了一些。很多操作表面上只是换了一种写法，实际区别却是有没有创建新数据、修改会不会影响另一边，以及数据此刻位于 CPU 还是 GPU。

## 避免不必要的内存开销

普通的 `y = y + x` 会先得到一个新的结果，再让 `y` 指向它。如果希望保留原来的 Tensor 对象，可以通过索引写回，或者把运算结果直接输出到 `y`：

```python
x = torch.arange(3,9).view(2,3)
y = torch.arange(2,8).view(2,3)
id_before = id(y)
# ... 省略输出
y[:,:] = y + x
print(id_before)
print(id(y))

# ... 重新创建 x 和 y
torch.add(x, y, out=y)
```

代码里用 `id(y)` 对比运算前后的 Python 对象。`y = y + x` 会改变 `y` 所指向的对象，而切片赋值和 `out=y` 都是在原来的 Tensor 上写入结果。现在的数据量很小，看不出多少性能差异，但以后模型里反复处理大批量数据时，这类额外分配就值得留意了。

## Tensor 和 NumPy 不一定是两份数据

接下来是 Tensor 与 NumPy 数组之间的转换关系：

```python
x = torch.ones(5,3)
y = x.numpy()
x += 1
print(x, y)

a = np.ones(5)
b = torch.from_numpy(a)
a += 1
print(a, b)

c = torch.tensor(a)
```

`x.numpy()` 和 `torch.from_numpy(a)` 都可能让两边共享底层数据，因此修改其中一边，另一边也会跟着变化。`torch.tensor(a)` 则会复制数据，得到的 `c` 不再随 `a` 一起改变。

这部分让我想到前面学过的 `view()` 和 `clone()`：真正需要判断的不是“转换之后变量名变没变”，而是底层数据有没有被复制。变量看起来是两个，内存里却未必真有两份独立的数据。

## 把 Tensor 放到 GPU 上

最后是 Tensor 在 CPU 和 GPU 之间的移动：

```python
if torch.cuda.is_available():
    device = torch.device("cuda")
    y = torch.randn_like(x, device=device)
    x = x.to(device)
    z = x + y
    print(z.to("cpu", torch.double))
```

`to()` 不只可以移动设备，也能同时改变数据类型。进行运算的 Tensor 需要位于同一个设备上，所以代码先把 `x` 移到 GPU，再与直接创建在 GPU 上的 `y` 相加，最后把结果转回 CPU。
